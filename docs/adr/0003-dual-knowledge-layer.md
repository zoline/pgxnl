# ADR-0003: 스키마 용어집과 비정형 문서 지식 레이어를 분리

- **상태**: Accepted
- **날짜**: 2026-08

## Context

기존 pgxrsa의 `glossary_store`는 "컬럼 업무 용어집"으로, `describe_table` 도구에
동적으로 주입되는 구조였다. 그런데 실무에서 필요한 지식 소스는 성격이 다른 두
가지로 나뉜다.

1. **코드-값 매핑** (예: `status = 'A'`는 "완납"을 의미): 짧고, 구조화에 가깝고,
   컬럼/테이블에 직접 연결된다.
2. **서술형 매뉴얼/업무 규정** (예: 대출 자격 요건을 설명하는 문서): 장문이고,
   비정형이며, 문맥을 읽어야 관련 규칙을 찾을 수 있다.

BIRD 벤치마크의 `financial`/`california_schools` DB로 진행한 실증 실험에서, 두
성격의 지식을 하나의 청킹·검색 전략으로 처리했을 때 검색 정밀도가 떨어지는 것을
확인했다. 특히 필드명이 유사한 코드 체계(DOC vs SOC)가 섞인 문서에서는, 원자적
단위로 쪼개도(용어집화해도) 진짜 도메인 모호성은 완전히 해소되지 않고, 반대로
서술형 문서를 무리하게 원자적 단위로 쪼개면 문맥이 손실된다는 것도 확인했다.

## Decision

두 지식 소스를 **별도 컴포넌트, 별도 저장소**로 분리한다.

- `governance/glossary.py` (`GlossaryStore`): 코드-값 매핑, 컬럼/테이블에 직접
  연결. `pgxnl_glossary` 테이블. §5.11(거버넌스 레이어)에 소속.
- `knowledge/document_store.py` (`DocumentStore`): 장문 비정형 문서 청킹·임베딩·
  검색. `pgxnl_document_chunks` 테이블(별도 pgvector 인덱스). §5.10에 소속.

두 컴포넌트 모두 `None`이면 완전 비활성화되는 독립적인 Provider로 구현한다
(ADR-0005 참고).

## Consequences

- **장점**: 각 소스에 맞는 검색 전략(용어집은 정확 매칭/구조 조회, 문서는 임베딩
  기반 유사도 검색)을 독립적으로 튜닝할 수 있다. 갱신 주기도 다르다 — 용어집은
  관리자가 수시로 등록/수정하고, 문서는 매뉴얼 개정 시 재수집한다.
- **트레이드오프**: 저장소가 두 개로 늘어 인프라 복잡도가 소폭 증가한다. 어떤
  지식이 어느 저장소에 들어가야 하는지 등록 시점에 판단이 필요하다(모호한 경우
  존재 가능).
- **후속 검토**: 문서를 "코드값 표 같은 정형적 부분"과 "서술형 부분"으로 나눠
  전자만 자동으로 용어집에 흡수시키는 하이브리드 파이프라인(문서→KB 자동 추출)을
  검토할 수 있으나, 이는 별도 ADR 대상으로 남겨둔다 — 오늘 실험에서 이 방식이
  청크 단위 혼동은 줄이지만 필드 간 어휘 중복(진짜 도메인 모호성)까지는 해결하지
  못한다는 한계가 확인됐기 때문에, 검색 시 필드/컬럼 스코프 정보를 함께 주는
  하이브리드 검토가 선행되어야 한다.
